# Security audit — 2026-09-26

## Result

**FAIL at audit time.** Finding 1 (High) and findings 2–3 (Medium) are blocking. The fixes are listed in "Resolution" at the end.

Scope: whole repository at commit `b203b30`, spec 001, constitution §3.

Independence caveat: the same agent session wrote the code and ran this audit. Planted defects (Evidence §3) reduce, but do not remove, confirmation bias. An independent review is recommended before a public release.

| Input | Trust | Reaches |

## Findings

### Finding 1 — Go toolchain with known standard-library vulnerabilities
**Severity**: High
**CWE**: CWE-1395 (dependency on vulnerable third-party component)
**Evidence**: `govulncheck` reports 5 reachable vulnerabilities in go1.26.4: GO-2026-6218 (`net/url`, fixed 1.26.6), GO-2026-6090 and GO-2026-5856 (`crypto/tls`), GO-2026-5972 (`encoding/asn1`), GO-2026-5026 (`net/http`).
**Impact**: `net/url` parses the untrusted URL argument, the first gate of the allowlist. `crypto/tls` and `net/http` protect the model download.
**Mitigation**: pin `toolchain go1.26.6` in `go.mod`.

### Finding 2 — `--force` rewrites archived files
**Severity**: Medium
**CWE**: CWE-706 (use of incorrectly-resolved name or reference)
**Evidence**: `app.transcribe` calls `vault.Replace(existing)` for any dedup hit. `dedup_dirs` includes `08-ARCHIVE/approved` and `08-ARCHIVE/disapproved`.
**Impact**: `--force` on a video that the pipeline already archived silently modifies the archive. The pipeline never sees the new clipping, and the archived record stops matching its manifest hash.
**Mitigation**: replace only when the existing file is inside `out_dir`. Otherwise save a new clipping in `out_dir`.

### Finding 3 — Markdown injection from uploader-controlled text
**Severity**: Medium
**CWE**: CWE-116 (improper encoding or escaping of output)
**Evidence**: `transcript.cleanText` strips `<tags>` and collapses whitespace, but keeps `![alt](https://…)` and `[[…]]`. Manual captions are written by the uploader.
**Impact**: a remote image in a caption loads when the clipping opens in Obsidian, which leaks the reader's IP address (tracking pixel). A `[[wikilink]]` pollutes the vault graph and the pipeline's link analysis. Code fences cannot form, because text never starts a line.
**Mitigation**: escape `[`, `]` and `!` in body text before rendering.

### Finding 4 — Invisible and bidirectional characters in file names
**Severity**: Low
**CWE**: CWE-451 (user interface misrepresentation)
**Evidence**: `vault.sanitize` removes `unicode.IsControl` (Cc) only. U+202E (right-to-left override) and U+200B (zero-width space) are Cf and pass through.
**Impact**: a title can make a file name look different from its real name in Finder and Obsidian.
**Mitigation**: also remove `unicode.Cf` characters.

### Finding 5 — Model download follows redirects to plain HTTP
**Severity**: Low
**CWE**: CWE-757 (algorithm downgrade)
**Evidence**: `model.Install` uses the client redirect policy. Go follows `https` → `http` redirects.
**Impact**: integrity is still enforced by size and SHA-256, so impact is limited to exposing which model is downloaded.
**Mitigation**: reject non-https redirects in `CheckRedirect`.

### Finding 6 — Check-then-rename race in `vault.Save`
**Severity**: Low
**CWE**: CWE-367 (TOCTOU)
**Evidence**: `os.Lstat` then `os.Rename` in `vault.Save`.
**Impact**: a file created between the two calls with the same name is overwritten. Requires a concurrent writer in the inbox.
**Decision**: accepted for v1 (single user, one run at a time).

### Informational — gosec
- G204 `exec.CommandContext` with variable: by design. Arguments are a slice, never a shell, and the binary names are constants.
- G304 file paths from variables: paths come from the temp dir, the config file or the vault. None comes from remote input.
- G301 `0755` for the model directory, and G104 ignored cleanup errors: deliberate, no security impact.

### Residual risks, accepted
- Transcript text reaches the pipeline-drain LLM phases. F1/F2 already treat sources as untrusted data (`untrusted-ingest`).
- Binaries resolve through `PATH`, and `--ignore-config` does not disable yt-dlp plugins in the user's home. Both are under local user control.

## Evidence

1. `go run golang.org/x/vuln/cmd/govulncheck@latest ./...`: 5 reachable standard-library vulnerabilities (Finding 1).
2. `go run github.com/securego/gosec/v2/cmd/gosec@latest ./...`: 9 issues, all triaged above.
3. Planted defects in scratch copies, all detected by the test suite:
   - allowlist changed to suffix matching: `url_test.go` fails on `evilyoutube.com`
   - `--` removed before the URL: `tools_test.go` fails
   - cookie path added to error messages: `run_test.go` fails with "stderr leaks the cookie path"
   - frontmatter quoting removed: `render_test.go` fails
4. Secret scan (`grep` for key/secret/token/password assignments): no matches. Fixtures contain no IP addresses and no signed media URLs.

## Independent review (shield, 2026-09-26)

A separate reviewer re-audited commit b45eee5 without the author's context. Verdict: **FAIL**, with 2 blocking findings. The review also showed that the fix for finding 3 above was incomplete. Captions decode HTML entities after tags are stripped, so `&lt;img&gt;` reached the note as a live `<img>` tag.
